# 티스토리 발행 (브라우저)

`tistory-publish`가 만들어 둔 **발행용 본문과 매니페스트를 그대로 올린다.** 본문을 만들거나 고치는 스킬이 아니다.

## 절대 원칙

- **본문을 타이핑하지 않는다.** 수백 줄을 타이핑하면 중간에 문자가 섞여 들어가고, 마크다운 마커가 소실된다. 사용자가 클립보드로 붙여넣게 하고, 나는 커서 위치만 잡는다.
- **본문을 수정하지 않는다.** frontmatter 제거·H1 제거·줄바꿈 변환은 이미 끝나 있다. "정리가 안 된 것 같다"고 판단되면 **잘못된 파일을 보고 있는 것이다** — 매니페스트의 `body_path`를 다시 확인한다. `Blog-drafts/`의 원본은 frontmatter와 H1이 있는 게 정상이고, 그건 붙여넣을 파일이 아니다.
- **내가 예전에 만든 정리본이 있어도 쓰지 않는다.** 초안은 교체될 수 있다. 진실은 언제나 이번에 받은 매니페스트다.
- **추론과 실측을 구분해서 보고한다.** 화면으로 확인한 것과 "그럴 것이다"라고 판단한 것을 섞지 않는다. 확인 못 한 항목은 못 했다고 말한다.
- **공개 전환은 사용자가 결정한다.** 비공개 저장까지만 하고 멈춘다.

## 실행 순서

### 1. 매니페스트 읽기

`Scratch/<slug>-발행.json`을 읽는다. 경로를 못 받았으면 **묻는다.** 짐작해서 아무 md나 열지 않는다.

매니페스트에 있는 것:

| 키 | 용도 |
|---|---|
| `title` | 제목란에 넣을 문자열 (앞뒤 따옴표까지 그대로) |
| `body_path` | 붙여넣을 본문 파일 |
| `chars` / `lines` | 붙여넣기 검증값 |
| `counts` | H2·H3·표·인용·리스트·링크·코드펜스 개수 |
| `must_be_zero` | 전부 0이어야 함 (frontmatter·H1·위키링크·이미지슬롯·인용마커·CR·상대경로) |
| `first_line` | 본문 첫 줄 |
| `links` | 발행 후 확인할 링크 목록 |
| `image_slots_removed` | 에디터에서 직접 넣어야 할 이미지와 그 위치 |

`body_path`를 읽어 `chars`·`lines`·`counts`가 실제로 맞는지 먼저 대조한다. **어긋나면 붙여넣지 말고 사용자에게 알린다** — 매니페스트가 낡았거나 파일이 바뀐 것이다.

### 2. 에디터 열기

1. 티스토리 새 글쓰기로 이동
2. 에디터를 **마크다운 모드**로 전환 (기본모드/마크다운/HTML 중)
3. 제목란에 `title`을 입력
4. 본문 편집기 안에 커서를 놓는다

### 3. 붙여넣기 요청 후 대기

여기서 **멈추고** 사용자에게 "붙여넣어"라고 말한다. 사용자가 `Ctrl+V`를 누른다. 그동안 편집기 안에서 **아무 키도 누르지 않는다** — 스크롤조차 키 입력으로 하지 않는다. 방향키·PageUp 같은 키가 문자로 입력되는 사고가 실제로 있었다.

사용자가 "됐어"라고 하면 다음으로 간다.

### 4. 붙여넣기 검증

에디터 내용이 매니페스트와 일치하는지 센다.

- 문자수 `chars`, 줄수 `lines` (끝 개행 때문에 1줄 차이는 정상)
- `counts`의 각 항목
- 첫 줄이 `first_line`으로 시작하는지
- `must_be_zero` 항목이 실제로 0인지 — 특히 맨 위에 `---`나 `stage:`가 보이면 **잘못된 파일이다**

**문자수가 정확히 일치하는 것이 가장 강한 신호다.** 하나라도 어긋나면 붙여넣기가 잘린 것이므로, 저장하지 말고 사용자에게 다시 붙여넣어 달라고 한다.

### 5. 비공개 저장 후 렌더링 확인

비공개로 저장하고 발행된 글을 열어 확인한다.

- **구조**: `h1` 0개, `h2`/`h3`/`table`/`li`/`a` 개수가 `counts`와 맞는지
- **위계**: H2와 H3가 시각적으로 구분되는지 (H2는 굵고 아래 밑줄, H3는 한 단계 작고 회색조)
- **frontmatter 누출**: 글 맨 위에 가로줄이나 `stage:` 텍스트가 없는지
- **`<br>` 개수**: 리스트 항목 중간에서 문장이 끊기는 게 있는지. 있으면 소프트 줄바꿈이 안 합쳐진 것이므로 사용자에게 알린다 (인용 블록 안의 `<br>`은 정상)
- **표**: 파이프 문자가 그대로 보이지 않고 표로 그려졌는지
- **mermaid**: `counts.code_fences`가 0이 아니면, 다이어그램이 SVG로 렌더링됐는지
- **링크**: `links` 중 표본 3개를 **실제로 클릭해서** 열리는지 확인한다. GitHub은 큰 마크다운 렌더에 10~20초 걸리므로 기다렸다 판단한다 — 성급하게 보면 "앵커가 안 먹는다"고 오판한다. 404가 나면 즉시 보고한다
- **콘솔 에러**

### 6. 보고

확인한 것과 확인하지 못한 것을 나눠서 보고한다. `image_slots_removed`가 비어 있지 않으면 **어디에 무슨 이미지를 넣어야 하는지** 위치와 함께 알린다.

공개 전환은 하지 않는다. 사용자가 결정한다.

## 하지 말아야 할 것

- **이미 발행된 글의 편집 화면을 열지 않는다.** 티스토리 에디터를 다시 열어 저장하면 코드블록의 언어 클래스가 소실된다(`language-mermaid` → highlight.js 오탐지로 덮어씀). `counts.code_fences`가 0인 글은 예외로, 재편집해도 잃을 게 없다.
- **스킨 편집기에 코드를 타이핑하지 않는다.** 스킨을 건드려야 하면 사용자가 클립보드로 붙여넣게 하고, 오염이 의심되면 부분 수정(Ctrl+Z)이 아니라 **블록을 통째로 다시 붙여넣는다.** CodeMirror의 undo는 서로 다른 위치의 삽입을 각각 별개 단위로 처리해서 한 번으로 다 안 돌아간다.
- **본문 변환을 대신 해주지 않는다.** 매니페스트가 없거나 본문이 정리돼 있지 않으면, 직접 자르지 말고 Claude Code 쪽에서 `tistory-publish`를 돌려야 한다고 말한다.
