# 티스토리 발행 준비

`Blog-drafts/`의 초안을 **붙여넣기만 하면 되는 상태**로 만들고, 브라우저 쪽에 넘길 매니페스트를 남긴다.

vault 규칙은 vault의 `CLAUDE.md`의 **6단계: 티스토리 발행**에 있다. 이 스킬은 그 규칙의 실행 도구다. 규칙과 이 파일이 어긋나면 `CLAUDE.md`가 우선이고, 이 파일을 고친다.

## 절대 원칙

- **본문 문장은 수정하지 않는다.** 이 스킬이 하는 일은 제거(frontmatter·H1·이미지 슬롯)와 줄바꿈 정규화뿐이다. 문장을 다듬고 싶어져도 손대지 않는다. 다듬을 것이 있으면 사용자에게 말하고, 고치는 건 원본(`Blog-drafts/`)에서 한다.
- **원본과 발행용 사본은 한 파일이 겸할 수 없다.** 원본은 vault 규칙(frontmatter·위키링크)을 지켜야 하고 발행본은 그걸 다 벗겨야 한다. 발행용은 언제든 재생성 가능한 파생물이므로 `Scratch/`(git 제외)에 둔다.
- **구조가 변하면 중단한다.** 변환 전후로 H2·H3·표·링크·리스트·코드펜스 개수가 하나라도 달라지면 스크립트가 실패한다. 숫자를 맞추려고 스크립트를 우회하지 말고, 왜 변했는지 먼저 본다.
- **수치를 눈으로 세지 않는다.** 검증값은 전부 스크립트가 계산해 매니페스트에 적는다. 모델이 세면 틀린다.

## 실행 순서

### 1. 초안 확인

인자로 경로를 받았으면 그것을, 못 받았으면 `Blog-drafts/`를 훑어 `status: 초안`인 것을 보여주고 **어느 글인지 묻는다.** 추측해서 아무거나 열지 않는다.

초안을 읽고 아래를 사용자에게 먼저 보고한다.

- 줄수·문자수, H2/H3 개수
- 표·코드블록·mermaid 유무
- **이미지 슬롯 `{이미지: ...}` 개수** — 있으면 제거 대상이고 삽입 위치를 따로 알려줘야 한다
- **vault 밖을 가리키는 상대경로 링크** — 있으면 2단계로
- **인용 마커 잔재**(`citeturn...` 같은 것) — 대화에서 복사할 때 딸려온다. 있으면 그게 붙어 있던 **문장까지 같이 지우지 말고**, 그 문장이 주장하는 내용을 3단계에서 검증한다

### 2. 링크 점검 (vault 밖 참조가 있을 때만)

상대경로 링크(`./report.md`, `../eval/x.md`)는 티스토리에서 100% 죽은 링크가 된다. 그러면 "근거: 리포트 3.2절" 같은 문장이 독자가 확인할 수 없는 주장이 된다.

- 대상 레포가 공개인지 `gh repo view <owner>/<repo> --json visibility`로 확인한다
- 파일이 실재하는지 `gh api repos/<owner>/<repo>/git/trees/HEAD?recursive=1`로 확인한다. **경로를 지어내지 않는다.**
- 공개·실재가 확인되면 `https://github.com/<owner>/<repo>/blob/<기본브랜치>/<경로>` 로 바꾼다
- 섹션 앵커까지 걸 때는 **슬러그를 손으로 계산하지 않는다.** GitHub은 한글 제목에서 특수문자를 규칙대로 제거하는데(`①` 등은 사라진다) 틀려도 페이지는 열려서 조용히 엉뚱한 곳으로 간다. 렌더된 페이지에서 실제 앵커를 뽑아 대조한다
- 레포가 비공개면 사용자에게 **공개할지, 수치를 본문에 흡수할지** 묻는다. 링크만 떼면 근거가 사라진다

### 3. 외부 주장 검증 (문헌·연구·제품 사양을 인용할 때만)

초안이 논문·연구·출시일 같은 외부 사실을 말하면 **원문을 실제로 연다.** 검색 결과 요약만 보고 인용하지 않는다 — 요약은 여러 출처를 뭉뚱그려서, 그 문헌이 말하지 않은 것을 말한 것처럼 보이게 만든다.

확인되면 본문에 출처 링크를 건다. 확인이 안 되면 그 문장을 지우지 말고 **사용자에게 무엇이 확인 안 됐는지 보고**한다.

### 4. 발행용 사본 생성

```
python <skill>/scripts/make_post.py "<Blog-drafts/초안.md>" "<vault>/Scratch" --slug <짧은영문슬러그>
```

슬러그는 파일명에 한글·공백·괄호가 섞이면 경로 전달에서 사고가 나므로 **짧은 ASCII**로 준다 (`part2`, `verifier-kpt` 등).

스크립트가 하는 일:

1. frontmatter 제거 (`title:` 필드가 있으면 제목으로 채택)
2. 최상단 H1 제거 (없으면 frontmatter `title:`이 제목)
3. 이미지 슬롯 제거 + 삽입 위치 기록
4. 소프트 줄바꿈 합치기 — 티스토리가 이걸 `<br>` 강제 개행으로 바꾸기 때문. 표·코드블록·헤딩·리스트·인용은 줄 구조가 의미라 건드리지 않는다
5. 구조 지문 대조 (어긋나면 실패, 파일 안 씀)
6. `must_be_zero` 확인 (frontmatter·H1·위키링크·이미지슬롯·인용마커·CR·상대경로)

산출물은 `Scratch/<slug>-발행용.md` 와 `Scratch/<slug>-발행.json`.

**실패하면 숫자를 맞추려 들지 말고 원인을 찾는다.** 구조가 변했다는 건 변환이 뭔가를 망가뜨렸다는 뜻이다.

### 5. 사용자에게 인계

아래를 보고한다.

- 매니페스트 경로 (크롬 쪽에 넘길 것)
- 제목 — 앞뒤 따옴표까지 그대로
- 줄수·문자수·구조 지문
- **제거한 이미지 슬롯의 삽입 위치** — 에디터에서 직접 넣어야 한다
- 링크 개수

그리고 **본문을 클립보드에 올린다** (PowerShell `Get-Content <body_path> -Raw -Encoding utf8 | Set-Clipboard`). 브라우저에 붙여넣는 것은 타이핑보다 안전하다.

브라우저 쪽 작업은 `tistory-publish-browser` 스킬이 매니페스트를 읽어서 한다. 사용자에게 **매니페스트 경로만** 크롬에 전달하라고 안내한다.

### 6. 발행 후 vault 기록

발행 URL을 받으면:

- `Blog-drafts/[제목].md`의 frontmatter에 `status: 발행`, `published_url: <URL>`
- `index.md`의 블로그 초안 목록 줄에 상태와 URL 반영
- `log.md`에 한 줄 — `| 날짜 | 작업 | 환경 | 근거/결과 | 확인 필요 |` 형식, **환경** 칸 필수
- 커밋 (푸시는 사용자가 요청할 때만)

## 알아둘 함정

이번 vault에서 실측으로 확인된 것들이다. 자세한 근거는 `CLAUDE.md` 6단계에 있다.

- **티스토리는 발행 시 `data-ke-size` 속성을 제거한다.** 스킨 CSS에서 속성 선택자를 쓰면 조용히 실패한다
- **발행된 글을 에디터에서 다시 열어 저장하면 `class="language-mermaid"`가 영구 소실된다.** 코드블록·mermaid가 있는 글은 재편집하지 말고 vault 원본을 고쳐 다시 붙여넣는다. 반대로 코드펜스가 0개인 글은 재편집해도 잃을 게 없으므로, 이미지 삽입 같은 작업을 나중에 해도 된다 — 매니페스트의 `counts.code_fences`로 판단한다
- **스킨 편집기(CodeMirror)에 코드를 타이핑으로 넣지 않는다.** 오염되면 부분 수정 말고 블록을 통째로 다시 붙여넣는다
